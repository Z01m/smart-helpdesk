# Knowledge Base Service

Порт: **8083**. Хранит статьи и категории, выполняет полнотекстовый поиск и возвращает фрагменты статей для RAG в ai-worker.

## Как работает создание статьи

`ArticleService.create` принимает `ArticleRequest`: заголовок, текст и необязательный `categoryId`. Возвращает сохранённую статью с UUID, категорией, датами и версией.

`ChunkingService.split` делит текст на фрагменты примерно по 2000 символов с перекрытием 200 символов. Перекрытие сохраняет контекст на границах. Это приближение к размеру в токенах из ТЗ, без отдельного токенизатора.

`EmbeddingService.embed` принимает список фрагментов, добавленных к заголовку, и обращается к Ollama `/api/embed`. Возвращает по одному вектору на фрагмент. Проверяет число результатов, размерность, отсутствие NaN/Infinity и нулевых векторов.

После получения всех embeddings `ArticleRepository.save` сохраняет статью и фрагменты в одной короткой транзакции. Для обновления прежние фрагменты заменяются новыми. Ошибка откатывает замену целиком. Если во время обращения к Ollama статью уже изменил другой запрос, возвращается 409 — повтори обновление.

## API

Для публичного API нужен JWT gateway. Читать могут авторизованные пользователи; создавать, обновлять, удалять и переиндексировать — ADMIN.

| Метод | Адрес | Назначение |
|---|---|---|
| POST | `/api/v1/articles` | Создать статью, 201 + Location |
| GET | `/api/v1/articles/{id}` | Получить статью |
| PUT | `/api/v1/articles/{id}` | Заменить статью и embeddings |
| DELETE | `/api/v1/articles/{id}` | Удалить статью с фрагментами, 204 |
| POST | `/api/v1/articles/{id}/reindex` | Пересоздать embeddings |
| GET | `/api/v1/articles?query=пароль&category=UUID&page=0&size=10` | Поиск и фильтрация, все параметры необязательны |
| GET/POST | `/api/v1/categories` | Список / создание категории |
| POST | `/internal/v1/knowledge/search` | Поиск для ai-worker |
| GET | `/actuator/health` | Проверка состояния |

Тело создания/обновления: `{"title":"Сброс пароля","content":"Инструкция...","categoryId":null}`. Создание категории: `{"name":"Аккаунт"}`. Дублирующаяся категория возвращает 409; неизвестная категория статьи — 400.

Внутренний поиск требует `X-Internal-Api-Key` и принимает **либо** `{"embedding":[...768 чисел...],"topK":5}` (существующий контракт ai-worker), **либо** `{"query":"Как сбросить пароль?","topK":5}`. `topK` от 1 до 50. Ответ: `{"chunks":[{"articleId":"UUID","title":"...","text":"...","score":0.89}]}`. Пустая база возвращает пустой список.

Полнотекстовый поиск использует PostgreSQL `tsvector` с русским словарём и ранжированием. Векторный поиск использует pgvector, cosine similarity `1 - cosine distance`: большее число означает более близкий фрагмент. Порог релевантности и ограничение контекста остаются в ai-worker.

## Конфигурация и запуск

Нужны PostgreSQL **с расширением pgvector** и Ollama. Docker Compose проекта уже использует образ pgvector и создаёт БД `knowledge_base` при первом запуске нового тома. Для существующего тома отсутствующую БД нужно создать отдельно, без удаления данных.

В Ollama нужна модель `nomic-embed-text`: `ollama pull nomic-embed-text`. Размерность зафиксирована в миграции и проверках как **768**. Модель и её версия должны совпадать с ai-worker. Смена модели требует переиндексации всех статей; смена размерности — новой миграции и изменения проверки векторов.

Переменные: `KNOWLEDGE_BASE_DB_URL`, `KNOWLEDGE_BASE_DB_USERNAME`, `KNOWLEDGE_BASE_DB_PASSWORD`, `KNOWLEDGE_BASE_PORT`, `AI_BASE_URL`, `AI_EMBEDDING_MODEL`, `INTERNAL_API_KEY`, `JWT_SECRET`. Значения по умолчанию рассчитаны на локальную инфраструктуру. Секреты совпадают с gateway/ai-worker.

Сборка из корня: `mvn -pl knowledge-base-service -am package -DskipTests`. Запуск: `java -jar knowledge-base-service/target/knowledge-base-service-1.0.0-SNAPSHOT.jar`.

## Аннотации и отличия от ТЗ

`@Valid` проверяет входной DTO: пустые поля, длину и topK. `@Repository` обозначает работу с БД. `@Transactional` на сохранении и удалении обеспечивает атомарность; запрос к Ollama выполняется до открытия транзакции. `@RestControllerAdvice` превращает ошибки в понятные HTTP-ответы.

Для компактности использован Spring JDBC вместо JPA/MapStruct: SQL поиска и преобразования pgvector видны явно. Индексация синхронная, отдельной очереди задач нет; недоступность Ollama возвращает 502 и не меняет статью. Индекс HNSW выбран вместо IVFFlat, чтобы не требовать начальной выборки для обучения индекса. Redis-кэш, отдельный circuit breaker и OpenAPI UI пока не добавлены. DTO ответа RAG совместим с уже написанным ai-worker; пределы контекста и его подготовка остаются в его `ContextBuilder`.
