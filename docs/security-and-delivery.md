# Доставка и безопасная конфигурация

## Что изменено

- WebSocket работает с несколькими экземплярами notification-service через общую PostgreSQL. Недоставленные уведомления повторяются после переподключения до подтверждения клиента.
- JWT передаётся в STOMP CONNECT, не в URL; истечение токена закрывает соединение. Разрешена только личная очередь. На узел ограничены соединения (1000), на пользователя — 5, размер кадра — 16 КиБ, очередь отправки — 64 КиБ, очереди исполнителей — 256. Origin задан точным списком, wildcard запрещён.
- Email включается отдельно, только после подтверждения адреса из подписанного JWT. Код одноразовый, действует 15 минут, новый запрос возможен через 10 минут. Коды в БД хешированы, адреса и очередь зашифрованы AES-256-GCM с привязкой к записи. Отправленные/отменённые полезные нагрузки очищаются.
- Письма отправляются из устойчивой очереди с блокировкой записи и арендой на 2 минуты. Ошибки повторяются с увеличением задержки, после 8 попыток видны в failedMessages. Пользователь может запросить повтор.
- Gateway фиксирует результат AI, историю статусов и processed_event одной транзакцией, после ошибки допускает повтор. Ошибки consumer направляются в DLQ вместо пропуска. Миграция V8 исправляет несовпадение enum и ограничений SQL, поле answer становится TEXT.

## Локальный и production-режим

По умолчанию HTTP сервисов и порты инфраструктуры Docker привязаны к 127.0.0.1. Для доступа из другого контейнера/хоста адрес SERVER_ADDRESS задаётся явно, вместе с правилами сети. Локальный Docker Compose предназначен для разработки: Kafka и PostgreSQL не следует публиковать в Интернет.

Для production включи SPRING_PROFILES_ACTIVE=prod. Нужны разные случайные JWT_SECRET (не менее 48 символов) и INTERNAL_API_KEY (не менее 32). Известные development-значения отклоняются. Эти проверки длины не измеряют энтропию — генерируй ключи криптографическим генератором, не паролями. Секреты БД передавай через SPRING_DATASOURCE_URL/USERNAME/PASSWORD и KAFKA_BOOTSTRAP_SERVERS; в prod они обязательны. Не записывай секреты в Git.

NOTIFICATION_ALLOWED_ORIGINS — точные HTTPS-origin фронтенда через запятую. В локальной разработке разрешён HTTP localhost/127.0.0.1. Перед сервисами нужен HTTPS/WSS reverse proxy с сертификатом, ограничением частоты запросов и размерами HTTP-запросов. Internal API, БД, Kafka и Ollama доступны только доверенной внутренней сети; при пересечении недоверенной сети требуется TLS/аутентификация транспорта. Профиль prod сам сертификаты и сетевые правила не создаёт.

## Включение Email

Задай EMAIL_ENABLED=true, EMAIL_FROM, EMAIL_ENCRYPTION_KEY (base64 от 32 случайных байт), SMTP_HOST, SMTP_PORT (обычно 587), SMTP_USERNAME и SMTP_PASSWORD. На всех экземплярах notification-service ключ шифрования одинаковый, хранится в secret manager/переменных окружения с ограниченными правами. Потеря ключа делает старую очередь и адреса недоступными; смена требует контролируемой перешифровки, её нельзя делать простым удалением старого ключа.

STARTTLS и проверка имени сертификата обязательны в prod. Пароль и адрес отправителя предоставляет владелец SMTP, приложение их не создаёт. Тестовый SMTP работает только на loopback и никуда не пересылает сообщения.

## Границы гарантий

Снять ограничения авторизации, Origin, сроков JWT и размеров сообщений было бы небезопасно; они сохранены. Абсолютную неуязвимость изменения кода не гарантируют.

При потере подтверждения WebSocket возможен повтор — клиент объединяет id. SMTP тоже не даёт exactly-once: авария после принятия письма сервером, но до записи SENT, может дать повтор. Уже переданное SMTP письмо отозвать при отписке нельзя. Новые письма после отписки не отправляются; очередь отменяется.

Подтверждение Email ограничено по аккаунту; перед публичным запуском нужен rate limiting регистрации/почты на входном прокси, чтобы регистрацией множества аккаунтов не обходили ограничение. Подписка добровольная, письма не содержат данные обращений.

Redis, OpenAPI UI, массовая рассылка операторам, circuit breaker и общий gateway-прокси остаются отдельными улучшениями. Размерность embedding 768 — часть схемы: смена модели требует переиндексации, а смена размерности — миграции. Такие операции нельзя безопасно заменить отключением проверки размерности.

## Последующие исправления по результатам тестов

Refresh-токен ротируется под блокировкой строки БД: несколько одновременных запросов не создают несколько действующих потомков. Gateway требует срок действия и UUID в access JWT и сверяет идентификатор с аккаунтом, загруженным из БД. Токен удалённого или пересозданного аккаунта возвращает 401.

AI-worker теперь сохраняет результат, processed_event и исходящее событие одной транзакцией. ResultOutboxPublisher повторяет отправку в Kafka с сохранённым eventId; повтор сетевой отправки возможен, поэтому downstream-consumer по-прежнему использует идемпотентность. Миграция V4 добавляет result_outbox. AI-вызовы ограничены по времени; consumer читает по одной записи и допускает до 15 минут обработки между poll.
