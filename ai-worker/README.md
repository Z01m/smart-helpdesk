# AI Worker

**Анализ обращений и подготовка ответов на основе базы знаний.**

Сервис получает новые тикеты из Kafka, определяет их категорию, эмоциональную окраску и приоритет, затем ищет подходящую информацию для ответа. Для AI-вызовов используется Ollama, для поиска справочного материала — Knowledge Base Service.

| Параметр | Значение по умолчанию |
|---|---|
| Служебный HTTP | `http://localhost:8081` |
| База данных | PostgreSQL · `ai_worker` |
| Зависимости | PostgreSQL, Kafka, Ollama, Knowledge Base Service |

## Как работает обработка

1. Consumer получает `ticket.created` с текстом обращения и данными, необходимыми для обработки.
2. Модель определяет категорию и тональность сообщения. На основе результатов и уровня клиента рассчитывается приоритет.
3. Текст вопроса преобразуется в **embedding** — числовой вектор, описывающий его смысл.
4. Worker передаёт вектор в Knowledge Base Service и получает подходящие фрагменты статей с оценками сходства.
5. Из релевантных фрагментов формируется контекст для модели. Модель готовит ответ, к результату добавляются ссылки на статьи-источники.
6. Если подходящего контекста нет, результат помечается как требующий участия оператора.
7. Результат и исходящее событие сохраняются в БД; outbox-публикатор отправляет `ticket.processed` в Kafka.

Это **RAG**: поиск информации в базе знаний перед генерацией ответа. Порог релевантности определяет, достаточно ли близок найденный материал к вопросу; он не является гарантией правильности ответа модели.

## Вход и результат

| Интерфейс | Назначение |
|---|---|
| Kafka · `ticket.created` | Входящие задания |
| Kafka · `ticket.processed` | Категория, приоритет, тональность, ответ, источники и признак участия оператора |
| HTTP · `POST /internal/v1/knowledge/search` на Knowledge Base Service | Поиск контекста |
| HTTP · Ollama | Анализ текста, embeddings и генерация ответа |

Задания поступают через Kafka. Порт `8081` предназначен для служебных endpoints Spring Boot, в том числе `/actuator/health`.

## Конфигурация

| Переменная | Значение по умолчанию / назначение |
|---|---|
| `AI_WORKER_PORT` | `8081` |
| `AI_WORKER_DB_URL` | `jdbc:postgresql://localhost:5432/ai_worker` |
| `AI_WORKER_DB_USERNAME` / `AI_WORKER_DB_PASSWORD` | Учётные данные БД |
| `KAFKA_BOOTSTRAP_SERVERS` | `localhost:9092` |
| `AI_BASE_URL` | `http://localhost:11434` |
| `AI_MODEL` | `qwen3:4b` |
| `AI_EMBEDDING_MODEL` | `nomic-embed-text` |
| `KNOWLEDGE_BASE_URL` | `http://localhost:8083` |
| `INTERNAL_API_KEY` | Общий ключ внутренних HTTP-запросов |
| `RAG_CONFIDENCE_THRESHOLD` | `0.75` — порог релевантности |
| `RAG_DEFAULT_TOP_K` | `5` — количество запрашиваемых фрагментов |

Embedding-модель должна совпадать с моделью Knowledge Base Service; текущая схема использует векторы размерности **768**.

## Запуск

Подними инфраструктуру, Ollama и Knowledge Base Service по [общей инструкции](../README.md). Из корня репозитория:

```shell
mvn -pl ai-worker -am package -DskipTests
java -jar ai-worker/target/ai-worker-1.0.0-SNAPSHOT.jar
```

Для автоматических ответов предварительно добавь в базу знаний статьи по темам обращений.
