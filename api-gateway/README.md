# API Gateway

**Аккаунты пользователей и жизненный цикл обращений Smart Helpdesk.**

Сервис принимает обращения от клиента, управляет доступом к ним и сохраняет результаты AI-обработки. Здесь находятся регистрация, вход, обновление токенов, назначение оператора и история изменения статусов.

| Параметр | Значение по умолчанию |
|---|---|
| HTTP | `http://localhost:8080` |
| База данных | PostgreSQL · `gateway` |
| Зависимости | PostgreSQL, Kafka |

## Что делает сервис

- Регистрирует пользователей и выдаёт access- и refresh-токены.
- Создаёт тикеты, возвращает обращения пользователя и отдельный тикет с результатом обработки.
- Контролирует права на просмотр, назначение оператора и смену статуса.
- Сохраняет историю статусов и публикует события через outbox.
- Получает результат AI из `ticket.processed` и записывает ответ, категорию, приоритет и другие данные в тикет.
- Возвращает владельца обращения Notification Service через защищённый внутренний API.

При создании тикета клиент передаёт текст проблемы; в ответ получает сохранённый тикет с идентификатором. AI-обработка выполняется асинхронно: результат можно получить позже через API тикета.

## HTTP API

| Метод | Адрес | Назначение |
|---|---|---|
| POST | `/api/v1/auth/register` | Зарегистрироваться |
| POST | `/api/v1/auth/login` | Войти и получить токены |
| POST | `/api/v1/auth/refresh` | Обновить токены |
| POST | `/api/v1/auth/logout` | Отозвать refresh-токен |
| POST | `/api/v1/tickets` | Создать обращение |
| GET | `/api/v1/tickets` | Получить страницу своих обращений |
| GET | `/api/v1/tickets/{id}` | Получить обращение и результат обработки |
| PATCH | `/api/v1/tickets/{id}/status` | Изменить статус с учётом прав и допустимых переходов |
| PATCH | `/api/v1/tickets/{ticketId}/assign` | Назначить оператора |
| GET | `/internal/v1/tickets/{ticketId}/owner` | Получить `ticketId` и `userId` для другого сервиса |

Для API обращений нужен заголовок `Authorization: Bearer <accessToken>`. Внутренний endpoint использует `X-Internal-Api-Key`. Пользовательские роли: `CUSTOMER`, `OPERATOR`, `ADMIN`.

Пример тела запроса создания обращения:

```json
{"message": "Не могу войти в аккаунт после смены пароля"}
```

## Обмен событиями

| Направление | Топик | Содержание |
|---|---|---|
| Публикация | `ticket.created` | Новое обращение для AI Worker |
| Получение | `ticket.processed` | Результат анализа и подготовленный ответ |
| Публикация | `ticket.status-changed` | Изменение статуса для Notification Service |

Данные тикета и исходящее событие записываются одной транзакцией. Outbox-публикатор отправляет событие в Kafka. Повтор полученного AI-события распознаётся по его идентификатору.

## Конфигурация и запуск

| Переменная | Назначение |
|---|---|
| `SERVER_PORT` | HTTP-порт, по умолчанию `8080` |
| `SPRING_DATASOURCE_URL` | JDBC-адрес БД, локально `jdbc:postgresql://localhost:5432/gateway` |
| `SPRING_DATASOURCE_USERNAME` / `SPRING_DATASOURCE_PASSWORD` | Учётные данные БД |
| `SPRING_KAFKA_BOOTSTRAP_SERVERS` | Адрес Kafka в локальном профиле |
| `KAFKA_BOOTSTRAP_SERVERS` | Адрес Kafka в профиле `prod` |
| `JWT_SECRET` | Ключ JWT, общий с Notifications и Knowledge Base |
| `INTERNAL_API_KEY` | Ключ внутренних запросов |

Из корня репозитория, после запуска инфраструктуры:

```shell
mvn -pl api-gateway -am package -DskipTests
java -jar api-gateway/target/api-gateway-1.0.0-SNAPSHOT.jar
```
